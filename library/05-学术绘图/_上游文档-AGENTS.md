# 仓库维护约定

本文件适用于本仓库。这里维护个人学术 Agent Skill 集合；项目规则只记录本仓库特有的组织、质量和维护要求。

## 目录与文件职责

- 每个 Skill 位于根目录下的独立文件夹，名称使用小写英文及连字符，与 `SKILL.md` 的 `name` 保持一致。
- 每个 Skill 提供 `SKILL.md` 和面向使用者的 `README.md`。按需增加 `scripts/`、`references/`、`assets/` 和工具适配目录，不创建无用途的空目录。
- 根目录 `README.md` 维护总目录与通用入口；子目录 README 维护用途、依赖、使用示例、输出和限制；`SKILL.md` 维护触发条件、执行流程和质量检查。
- Skill 应能随整个文件夹独立迁移。内部资源使用相对路径，不写入维护者电脑的绝对路径，不隐式依赖同级 Skill 的内部文件。
- 长篇 API 文档和背景资料放入 `references/`，由 `SKILL.md` 按需引用。事实只维护一份权威记录，其他文件通过链接引用。

## 学术质量与来源

- 不编造论文、DOI、引用、数据、统计结果或已完成的验证。无法核实的内容明确标注。
- 明确输入结构、单位、数据变换、统计假设及输出要求；不为迎合图形或结论擅自改变统计含义。
- 示例优先使用合成数据或来源、使用条件明确的公开数据，并提供复现命令；涉及随机过程时记录种子。
- 外部资料快照、改编内容和第三方代码需要记录来源、版本、许可及更新方式，通常放在该 Skill 的 `references/provenance.md`。
- 区分参考版本、实际运行版本和在线最新版本。不把本地快照描述成已核实的最新发布。
- 保留各 Skill 及第三方资料的许可证和署名；根目录许可说明不能替代子目录许可，也不能扩大第三方授权范围。

## 修改与验证

- 新增、删除或重命名 Skill，同步更新根目录 README 的目录表和受影响的链接。
- 改变用法、依赖、输出或限制，同步修改对应 Skill 的 README；执行行为变化时更新 `SKILL.md`。
- 修改参考版本时审查实际 API 和来源差异，按该 Skill 的更新说明重建资料，不只替换版本号。
- 文档修改检查相对链接、命令与现有文件是否一致；执行逻辑修改运行与改动相称的检查或已有测试。
- 绘图与文档输出涉及布局变化时查看实际产物。文件成功写出不等于内容或版式正确。
- 完成时说明已做的验证和未验证的部分；环境缺失时如实记录，不把提供脚本描述为测试通过。
- 不提交密钥、个人配置、真实研究中的非公开数据、缓存或本次临时产物。正式示例数据、图像和参考 PDF 可按需纳入版本控制，不按扩展名统一排除。

## 维护范围

仅在有实际需求时添加共享依赖、安装器、发布流程或 CI。各 Skill 可使用不同语言与依赖，不为仓库外观统一而改写已经可用的内部结构。
