# 04 · 如何想 Idea

想 Idea 主要分两步：**选择一个好的研究问题** → **寻求问题的解决方案**。

## 两种研究范式

| | Problem-driven | Method-driven |
|---|---|---|
| 逻辑 | 找一个重要的问题或目标，想办法把它做好 | 拿着锤子找钉子：基于已有技术方案，不断解决新问题 |
| 例子 | 大模型在某任务上性能不好，如何提上去？先定 1–2 个 benchmark，探索相关技术，目标是把任务做 work | GRPO 刚出来时拿来做多模态推理、Agentic RL；Skill 火时去解决数学/医疗/司法垂域问题 |
| 也可以 | 构建 benchmark：把一个问题定义清楚（比如游戏 Agent 方向，还没有 benchmark 支持某类评估，就定义一个新的） | — |
| 也可以 | 在领域通用 benchmark 上对已有方案做**问题分析**，找到关键挑战（如 GRPO 的效率问题、信用分配问题），再改进优化 | — |

> **大部分情况下更偏好 Problem / Goal-driven research**，在这个过程中再对 method 进行适配和优化。两种方式很多时候是融合的。

## 如何找到研究问题

### 切入 1 · 批判性论文阅读

在阅读过程中尝试"鸡蛋里面挑骨头"，多思考论文存在的不足和问题，从而提出新问题。

- 把"读文献"和"提问题"**绑在一起**，而不是分成两个阶段
- 主动思考"如果这篇论文换个数据 / 换个假设会怎样"

> **这个习惯越早养成越好。** 很多研究生前一两年读了大量文献却提不出问题，就是因为读的时候只在"理解"，没有在"批判性质疑"。

### 切入 2 · 从失败中寻找机会

- 思考当前主流方案有哪些 **failure case**
- 主动**寻找和复现** failure case
- 深入分析为什么会出现 failure case，探究背后的原因
- 尝试提出解决方案

### 切入 3 · 从"是否有效、为什么有效"反推机制

对一个**效果很好但缺乏解释**的方法，主动追问"它内部到底在做什么、为什么能 work"，通过设计实验做算法分析。

> 这类 "reverse-engineering" 式的问题往往比"设计一个新方法"**更容易找到明确的切入口**——因为你有一个已经确定有效的现象作为锚点，只需要设计实验或理论工具去拆解它，而不是从零猜一个新方法是否有效。

**代表案例**：清华大学黄高老师团队的 NeurIPS 2025 最佳论文提名
*Does Reinforcement Learning Really Incentivize Reasoning Capacity in LLMs Beyond the Base Model?*
https://arxiv.org/abs/2504.13837

## 自检清单：这个 Idea 值得做吗

拿下面几问过一遍，任何一问答不上来就该重新想：

1. 这个问题**真实存在**吗？还是我自己臆想的？
2. 什么场景会遇到它？解决了能带来什么好处？
3. 有没有**简单的方法**已经能解决？
4. 现有方法为什么不够好？不够好的**根本原因**是什么？
5. 我的方法为什么在**逻辑上**能解决它？（不只是"我试了效果好"）
6. 如果我做出来了，领域会因此往前挪一步吗？
