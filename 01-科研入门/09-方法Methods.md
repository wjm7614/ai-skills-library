# 09 · 如何写论文 · Methods

> **Methods 应当是论文中相对最好写的部分**，因为它主要回答一个问题：**本文的方法到底是怎么做的？**

## Methods 要讲清楚的五件事（AI 论文）

1. 方法的**核心思想**
2. **问题定义**和符号系统
3. **模型结构**或算法流程
4. 关键模块的**设计动机**
5. **公式、目标函数、推导过程**

## 推荐结构：总分结构

```
1. Overview              ← 先总体介绍方法
2. Problem Formulation   ← 定义问题和符号
3. Method Details        ← 分模块讲方法
4. Training / Optimization ← 训练目标和优化方式
5. Inference / Deployment  ← 测试或使用阶段如何运行
```

**好处**：读者先看到方法全貌，再逐步进入细节，**不会一开始就被公式、符号和模块名称淹没**。

## 先写 Overview

Methods 开头通常应先写一段 Overview，用来介绍方法的**核心思想**。

Overview 不需要写太多细节，而是要回答：

- 本文方法要**解决什么问题**？
- 方法的基本**出发点**是什么？
- 方法由哪些**主要模块**组成？
- 每个模块大致**负责什么**？
- 整体流程如何**从输入走到输出**？

> **Overview 应该和方法的主图配合使用：主图负责让读者"看见方法"，Overview 负责让读者"理解这张图"。**

→ 主图怎么画见 `12-论文画图指南.md`

## 单独写 Problem Formulation

AI 论文通常会出现很多字母、符号、变量、集合、函数和下标。

> **如果不提前定义清楚，读者后面读公式会非常吃力。**

建议做法：

- 用一张**符号表**列出所有记号（很多顶会论文都这么做）
- 定义顺序要符合阅读顺序：先用到的先定义
- 同一个符号不要在不同地方表示不同含义

## Method Details 的写法

每个模块建议按同一套模板展开：

1. **动机** —— 为什么需要这个模块？解决前文提出的哪个问题？
2. **设计** —— 具体怎么做？给出结构图 / 公式 / 伪代码
3. **与已有做法的区别** —— 为什么不直接用现成方案？

> 动机先行的好处：**审稿人不会觉得你在堆模块。** 每个模块都有存在的理由，而不是"A 也加上，B 也加上，效果就好了"。

## 常见错误

| 错误 | 后果 |
|---|---|
| 一上来就丢公式，没有 Overview | 读者迷失，审稿人读不下去 |
| 符号未定义就使用 | 公式无法理解，直接被扣分 |
| 模块没有动机，只是"我们也加了 XX" | 被认为在堆砌，novelty 被质疑 |
| 只写"怎么做"，不写"为什么这样做" | 缺少 intuition，读者无法判断合理性 |

## 自检

- [ ] 有没有独立的 Overview 段落？
- [ ] 主图和 Overview 是否对得上？
- [ ] 所有符号在使用前都定义了吗？
- [ ] 每个模块是否都写了设计动机？
- [ ] 读者能否只靠这一节复现方法（配合附录）？
