## 本目录的三条线

```
搭项目  →  01（四步法）        ← 开工前
验收    →  02（8 步法）        ← 每个功能做完
上线前  →  03 → 04 → 05        ← 上线前，逐条过一遍
```

**03 / 04 / 05 是同一件事的三个视角**：

- `03` 是**流程**（先看这个，知道整体怎么走）
- `04` 是**清单**（每项讲清风险 + 检查要点 + 你看什么）
- `05` 是**工具**（只放提示词，干活时开着这个复制）

### 三条视频的要点（用户整理提供）

三条要点已分别落到 `01`、`02`、`03` 三个文件。原始文本摘要：

1. **四大核心步骤**：拆模块（庖丁解牛）→ 分三层（界面-逻辑-数据）→ 先画蓝图再开工（Plan-Execute）→ 定对接规范（规格驱动）；外加**报错排查三步法**（先锁层 → 再追数据 → 最后精准改单个文件）；AI 写完代码让它自检边界问题
2. **验收 AI 搭的后端架构（8 步）**：先验规则 → 查目录责任 → 最小模块演练 → 接口返回要示例 → 复用框架少瞎封装 → 固定启动配置日志 → 汇总成架构文档 → 提交 Git 锁定版本
3. **上线前用 AI 做安全审计全流程**：按钱/权限/数据分风险等级 → 功能测试覆盖三类情况 → 做成自动回归测试 → 故意改错代码验证测试不是假的 → 让 AI 扮攻击者做接口攻防 → 先核对问题再修改 → 别过度测试优先保核心功能

## 21 张图为什么单独归档

这 21 张图**不是三条视频的截图**，而是一份独立的《Vibe Coding 代码安全自检清单》。它比视频要点详细得多，且每张都带**可直接复制的提示词**，因此按独立 skill 处理：

- 原件已从微信临时目录**抢救归档**到 `assets/`（临时目录会被清理，原件会丢）
- 图文内容已完整转成 Markdown（`04`），**离线可查、可被 AI 直接读取**
- 提示词单独抽出成 `05`，避免每次都要在长文里翻
