# 02 · 如何验收 AI 搭的后端架构（8 步）

> **来源**：抖音视频要点（用户整理提供）
> **面向**：**没有技术背景**的人
> **核心思路**：不用看懂代码，靠**规则、示例、证据**判断好坏 —— 免得后面代码越写越乱

---

## 核心原则

> **别听 AI 说「完成了」，得看它拿什么证明。**

这句话是整套 8 步的地基。AI 说"已实现"是零成本的，要它拿**可核对的东西**出来才是真的。

---

## 8 步验收法

### 第 1 步 · 先验规则

**让 AI 拿证据，不能只说"完成了"。**

- 要它指出：功能在哪个文件、哪几个函数
- 要它给出可执行的验证方式（命令 / 请求示例）
- 说"已实现"但拿不出位置的，一律按未完成处理

### 第 2 步 · 查目录责任

**别被目录数量忽悠，看职责清不清晰。**

- 目录多 ≠ 架构好
- 要看：**每个目录负责什么，边界清不清楚**
- 危险信号：一个文件里既处理请求又写数据库又算业务

### 第 3 步 · 最小模块演练

**试跑一下，看链路分不分层。**

- 挑一个最小功能，让它真正跑起来
- 观察数据怎么从请求 → 逻辑 → 数据库走完
- 如果一段代码同时干三层的活，说明**没分层**

### 第 4 步 · 接口返回要示例

**各种成功、失败场景都得有具体格式。**

要它给出每类情况的**真实返回示例**：

| 场景 | 要什么 |
|---|---|
| 正常成功 | 实际 JSON |
| 参数错误 | 实际 JSON |
| 未登录 | 实际 JSON |
| 无权限 | 实际 JSON |

> 只有"成功返回长这样"是不够的 —— **失败长什么样，决定了出问题时你能不能看懂**。

### 第 5 步 · 复用框架，少瞎封装

**能用框架自带的，就别自己写。**

- 自己造一套认证 / 校验 / 数据库封装，等于自己造 bug
- 框架自带的方案被无数人踩过，更安全也更省事

> 与安全清单第 07、09 项呼应：**"别信自造过滤"**、**"CSRF 用框架自带"**。

### 第 6 步 · 固定启动配置与日志

**把"怎么跑、连没连数据库"说清楚。**

- 启动命令是什么
- 环境变量有哪些、从哪读
- 连上数据库了没有、怎么确认
- 日志在哪、记了什么

### 第 7 步 · 汇总成架构文档

**关键规则都记下来。**

把前 6 步的结论沉淀成一份文档：目录职责、分层方式、接口约定、启动方式、验证方法。

> 这份文档是你后续验收的**基线** —— 下次 AI 改了东西，拿它对。

### 第 8 步 · 提交 Git 锁定版本

**最后提交 Git，锁定版本。**

- 验证通过的版本必须留档
- 后面改坏了能回到这个点
- 没有版本控制，前面 7 步的成果随时会丢

---

## 8 步速查

| # | 动作 | 一句话标准 |
|---|---|---|
| 1 | 先验规则 | 拿证据，不听结论 |
| 2 | 查目录责任 | 看职责，不看数量 |
| 3 | 最小模块演练 | 试跑，看分不分层 |
| 4 | 接口返回要示例 | 成功 + 各类失败 |
| 5 | 复用框架少瞎封装 | 别自造轮子 |
| 6 | 固定启动配置日志 | 说清怎么跑 |
| 7 | 汇总成架构文档 | 沉淀成基线 |
| 8 | 提交 Git 锁版本 | 留退路 |
