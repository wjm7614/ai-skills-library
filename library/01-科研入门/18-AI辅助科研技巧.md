# 18 · AI 辅助科研的一些 Tips

> 原始材料以 **Claude Code** 为例（LAMDA 课题组内部整理）。概念对绝大多数 AI Agent 工具通用。

## 一、上下文（Context）vs 记忆（Memory）—— 最关键的一对概念

| | 上下文 Context | 记忆 Memory |
|---|---|---|
| 是什么 | **当前这段对话** | **写进文件的项目约定** |
| 生命周期 | 临时的，退出当前会话就没了 | 持久的，清空上下文也不丢 |
| 问题 | 会话越长越满、越慢 | 需要主动维护 |

在 Claude Code 里，记忆对应 `CLAUDE.md` 文件。

> **核心认知**：想让 AI 长期遵守的规则，写进**记忆文件**；只在本次任务用到的信息，放在**上下文**里。很多人抱怨"AI 又忘了我说过的话"，根本原因是把该写进记忆的东西留在了上下文里。

## 二、常用快捷键 / 命令

| 操作 | 作用 |
|---|---|
| `!` | 执行会话外的 shell 命令，**输出会进入上下文** |
| `@` | 引用文件 / 路径（带自动补全） |
| `Command + J` / `Option + Enter` | 换行（不发送） |
| `Command + U` | 清空当前输入行 |
| `Command + R` | 搜索历史 prompt |
| `Command + V` | 粘贴截图 |
| `Esc` | **立刻打断**当前动作（不退出会话） |
| 双击 `Esc`（= `/rewind`） | 回退到之前某条消息 |
| `Shift + Tab` | 循环切换模式（见下） |

## 三、三种模式（按风险从低到高）

| 模式 | 行为 | 什么时候用 |
|---|---|---|
| **普通** | 每次动手前询问 | 不确定后果时 |
| **plan mode** | 只规划、不改文件；先规划后编码 | **复杂任务首选**，先看方案再决定 |
| **auto-accept edits** | 自动接受编辑、连续执行 | 任务明确、批量改动时 |
| `claude --dangerously-skip-permissions` | 允许所有操作 | 沙箱 / 隔离环境，慎用 |

> ⚠️ 名字里带 `dangerously` 不是装饰。在真实代码库上跑之前想清楚。

## 四、推理预算控制

在 prompt 里写 **`think` / `think hard` / `ultrathink`** → 逐级提高推理预算。

> 简单改个变量名不需要 ultrathink；设计架构时值得。

## 五、上下文管理命令

| 命令 | 作用 |
|---|---|
| `/compact` | 压缩成摘要后继续 —— 会话变慢 / 快满时用 |
| `/clear` | 彻底清空，换全新会话 |
| `/cost` | 查看本次 token 消耗 |
| `/init` | 扫描代码库、生成 `CLAUDE.md` 初稿 |

## 六、给科研场景的具体建议

### 1. 用 plan mode 做实验设计

让 AI 先输出实验方案（假设 → 变量 → 对照 → 评价指标），**你确认后再写代码**。避免写了一大堆代码才发现设计错了。

### 2. 让 AI 做"批判者"而不是"执行者"

- 让它读你的方法描述，然后**找出三个最可能被审稿人攻击的点**
- 让它扮演审稿人，给出负面意见
- 这比让它帮你润色文字有用得多

### 3. 复现实验时把环境写进记忆

随机种子、依赖版本、数据路径——这些写进记忆文件，避免每次重新交代。

### 4. 代码生成要能跑才算数

> **AI 的产出未经执行不算结果。** 生成的代码必须实际跑一遍，看报错，再修。

### 5. 不要用 AI 编造事实

不编造文献、不编造引用、不编造实验结果。AI 会一本正经地捏造参考文献——**每一条引用都要自己核实**。

## 七、红线

| 可以做 | 不可以做 |
|---|---|
| 让 AI 帮你理清思路 | 让 AI 替你决定研究方向 |
| 让 AI 生成代码骨架 | 直接提交未运行的代码 |
| 让 AI 扮演审稿人挑毛病 | 让 AI 编造实验数据 |
| 让 AI 润色表达 | 让 AI 伪造文献引用 |
